# Retro features: scope

[Français](MODULES.md)

| Item | First delivery | Contract and behaviour |
| --- | --- | --- |
| Retro panels/navigation | Yes | Render existing menus and blocks |
| 88×31 buttons | Yes if a suitable generic block exists | Media image, accessible text, validated HTTP(S) URL, order, grouping; no automatic remote images |
| What's-new log | Yes | Representation of already published news; no second editorial system |
| Retro gallery | Yes | Existing gallery, explicit links, captions and alt text; no automatic carousel |
| Neighbour links | Yes | Managed link collection, no tracker or third-party widget |
| GIFs/blinkies | After validation | Static counterpart required; no flashes; visitor chooses whether to start animation |
| Guestbook | Later module | Pending submissions, moderation, anti-bot protection and quotas, escaping, deletion; no unrestricted HTML |
| Automatic webring | Later module | Server-managed directory and stable previous/next links; no third-party scripts downloaded by the front end |
| Counter | Optional, later | Aggregate count through a suitable statistics module, without claiming unique-person counts; disabled by default |
| Scrolling banner | Outside v0.1 | Requires a stop control and static alternative; value still to be validated |

## Guestbook

Minimal public fields: nickname and message; publication date generated by the server. No public email and no email collection by default. States: pending, published, rejected. The server enforces maximum length, quotas, core anti-bot controls and moderation rules. Pending entries never appear in the public snapshot or site cache.

MMW could expose the guestbook via `requests` for moderation and `records` for reading, subject to the actual available contract. Read and publication permissions are separate. Any new primitive must support use cases beyond OldWeb.

Retention periods for unpublished submissions and anti-abuse logs must be configurable and documented before opening the module. Never export those records into design kits or Git.

## Webring

Start with manual links: enough to recreate the spirit of a website network. Future server-side URL checking must block private addresses, loopback, cloud metadata endpoints and unauthorised redirects, with DNS checks on every connection; otherwise there is an SSRF risk. This kit includes no arbitrary URL fetching.

## Deactivation

Disabling a style does not erase a guestbook. Disabling the module removes its public access and retains data according to its own policy. Uninstallation with deletion is a separate explicit operation. Exports distinguish site content, style settings and community data.
